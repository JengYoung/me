# 시리즈 수집·탐색 계약

[이슈 #14](https://github.com/JengYoung/me/issues/14)의 확정 범위다. 포스트 원고는 `apps/web/docs/posts/{postId}`에 유지한다. 시리즈에 편입하거나 순서를 바꾸어도 기존 글 주소·버전 이력·본문을 이동하거나 중복 저장하지 않는다. 일기는 시리즈 대상이 아니다.

새 글 생성부터 미리보기·검증·발행까지의 시작점은 [콘텐츠 작성·발행 안내](publishing.md)다. 이 문서는 시리즈 작성 예시와 세부 계약을 관리한다.

## 작성 예시

1. 포스트 생성 명령에서 시리즈를 지정하거나, 포스트 frontmatter에 다음 관계를 작성한다. 같은 시리즈의 다른 글은 같은 `id`와 서로 다른 `order`를 사용한다.

   ```yaml
   series:
     id: my-series
     order: 10
   ```

2. 저장소 루트에서 `pnpm dev`를 실행하면 실제 초안을 수집해 새 시리즈를 `apps/web/docs/series/series.json`에 등록한다. JSON 최상위 배열에서 해당 ID의 작성 필드를 편집한다. 다음은 항목 하나의 예시이며 기존 배열을 통째로 교체하지 않는다.

   ```json
   {
     "id": "my-series",
     "label": "시리즈 표시 이름",
     "title": "직접 입력할 시리즈 제목",
     "description": "직접 입력할 시리즈 소개",
     "thumbnail": "./my-series/cover.png",
     "derived": { "posts": [], "postCount": 0, "updatedAt": null }
   }
   ```

3. `thumbnail`을 사용하려면 예시 기준 `apps/web/docs/series/my-series/cover.png`에 이미지를 준비한다. 이미지가 없으면 이 필드를 생략하거나 비워 기존 캐릭터를 사용한다.
4. 저장한 뒤 <http://localhost:3000/series>에서 목록을, <http://localhost:3000/series?showType=carousel>에서 캐러셀을 확인한다. 시리즈 상세와 포스트의 시리즈 목차·이전/다음도 같은 집계를 사용한다.
5. `pnpm content:validate --drafts`로 검사한다. 제목·소개가 비었다는 오류가 나면 JSON에 남은 해당 ID의 필드를 채운 뒤 다시 실행한다. 공개 파일 준비와 빌드는 [발행 안내](publishing.md)를 따른다.

`derived`는 직접 편집하지 않는다. 공개 글만 집계하므로 초안만 있는 시리즈는 `posts: []`, `postCount: 0`, `updatedAt: null`이 정상이다. 개발 화면의 초안 포함 편수는 별도의 미리보기 카탈로그를 사용한다. 공개 집계를 다시 계산하려면 `pnpm --filter web content:generate`를 실행한다.

## 1. 단일 JSON과 작성 필드

- `apps/web/docs/series/series.json` 한 파일을 Git으로 관리한다. 배열의 각 항목은 `id`, `title`, `description`, 선택적인 `label`·`thumbnail`, 자동 계산되는 `derived`를 가진다. 시리즈 자체에 버전 파일·MDX·공개 이력을 만들지 않는다.
- 고정 `id`는 포스트의 `series.id`와 같으며 소문자 영문·숫자·하이픈을 사용한다. 새 ID를 수집하면 `label: ""`, `title: ""`, `description: ""`으로 등록한다. 이름·제목·소개를 자동 작성하지 않는다.
- `label`은 URL의 ID와 독립적인 시리즈 표시 이름이다. 목록·캐러셀·상세·포스트 챕터 탐색과 페이지 메타데이터는 공백을 제거한 `label`을 우선하고, 생략·빈 문자열·공백뿐이면 기존 `title` → `id` 순서로 표시한다. `label`이 문자열이 아니면 오류다. `title`·`description`의 필수 입력 검증은 그대로 유지하며 `label`로 대신 채우지 않는다. 이름 변경은 ID·원고의 `series.id`·주소·canonical을 바꾸지 않는다.
- 작성자는 `label`·`title`·`description`·`thumbnail`을 편집한다. 재수집은 이 값과 사용하지 않는 시리즈 항목을 보존한다. 삭제·ID 변경을 자동으로 수행하지 않는다.
- `derived`에는 공개 글의 `{ id, order }` 목록, `postCount`, `updatedAt`만 기록한다. 본문·과거 버전·초안 메타데이터를 넣지 않는다. 작성자가 파생 값을 수정해도 다음 수집에서 원고 기준으로 다시 계산한다.
- `thumbnail`은 `docs/series` 안의 이미지 상대 경로다. 예: `./building-my-blog/cover.png`. 생략·빈 문자열은 기존 캐릭터로 표시한다. PNG·JPEG·WebP·AVIF·GIF를 지원하고 누락 파일·폴더 밖 경로·외부 심볼릭 링크·공개용 `.local.` 자산을 거부한다. 실제 화면에서 참조하는 이미지만 정적 import하며 폴더 전체를 공개하지 않는다. 이미지에 포스트 버전 접두어를 요구하지 않는다.
- JSON 문법·스키마 오류는 원본을 덮어쓰지 않고 실패한다. 같은 입력에서는 같은 JSON을 만들고 내용이 다를 때만 저장한다. 저장 도중 작성자가 변경한 값도 덮어쓰지 않는다.

## 2. 공개 집계와 정렬

- 공개 시리즈는 포스트마다 숫자 버전상 최신 공개 발행본의 `series: { id, order }`로 구성한다. 같은 글의 과거 버전이나 초안을 별개 편으로 세지 않는다.
- `order`는 1 이상의 안전한 정수이며 같은 시리즈의 현재 글끼리 중복되면 오류다. `10, 20, 30`처럼 간격 있는 정렬값을 허용한다. 화면의 챕터 번호·N번째 글·현재 위치는 정렬 결과의 인덱스 + 1로 계산해 반드시 `1..N`으로 이어진다.
- 소속 글은 `order` 오름차순이다. 시리즈 모음은 소속 글의 최신 공개 버전 `publishedAt` 최댓값 내림차순이며 동률이면 시리즈 ID로 고정한다. 기존 글의 새 수정본도 시리즈 순서에 반영한다. 파일 수정 시각은 사용하지 않는다.
- 캐러셀의 최근 글 최대 3편은 포스트 최초 발행 시각인 `createdAt` 내림차순이다. 시리즈의 최근 수정 시각과 구분한다.
- 공개 글이 없는 정의는 JSON에 남기되 공개 목록·상세·사이트맵에서는 제외한다. 없는 ID와 공개 글이 없는 시리즈 상세는 404다. 과거 본문을 선택해도 시리즈 탐색은 현재 공개 구성을 따른다.

## 3. 생성·검증·미리보기

- `content:generate`, `content:validate`, 공개 빌드와 `pnpm dev`에 수집을 연결한다. 빌드는 검증 → 공개 카탈로그 생성 → Next.js 빌드 순으로 실행한다.
- `content:validate`와 공개 빌드는 JSON에 등록된 제목·소개 중 빈 문자열이나 공백만 있는 값이 있으면 실패한다. 오류는 JSON 경로·시리즈 ID·필드를 표시하고 새 빈 항목은 작성할 수 있게 남긴다. 이미지 참조도 검증한다.
- 개발 서버는 기존 포스트 미리보기 기준으로 현재 초안도 집계하고 원고·JSON·이미지 변경을 감지한다. 표시 이름·제목이 모두 미입력이면 화면에서 ID로 구분하며 JSON 값을 채우지 않는다. 미리보기 표시와 noindex를 유지한다.
- 미리보기 카탈로그는 공개 카탈로그와 별도로 생성한다. 개발 중에도 Git 관리 JSON의 `derived`는 공개 글만 기록한다. 초안 전용 시리즈를 공개 페이지·사이트맵·브라우저 산출물에 넣지 않는다.
- 생성 모듈은 `apps/web/entities/series/generated/`와 `generated-preview/`로 분리하고 Git에서 제외한다.
- 원고·자산을 자동 발행하거나 실제 원고를 검증용 샘플로 바꾸지 않는다. 수집·검증·발행 준비는 커밋·푸시·배포와 별개다.

## 4. 읽기 화면과 탐색

- `/series`는 기본 리스트, `?showType=carousel`은 캐러셀이다. 알 수 없는 값은 리스트로 처리하고 전환·새로고침·뒤로가기에 URL 상태를 유지한다.
- 리스트는 번호·제목·소개·글 수·최근 수정 시각·상세 이동을 제공한다. 데스크톱은 행으로, 모바일은 여러 줄로 배치한다.
- 캐러셀은 데스크톱 왼쪽에 설명·최근 글, 오른쪽에 대표 이미지를 두고 모바일에서는 이미지·설명 순으로 쌓는다. 이전·다음, 현재 위치/개수·막대, 모바일 가로 스와이프를 제공하고 자동 재생 없이 순환한다. 단일 시리즈에서는 불필요한 방향 조작을 숨긴다. 긴 모바일 설명은 펼치고 접을 수 있다.
- 제목·대표 이미지는 시리즈 상세로 연결한다. 스와이프 후 오인 클릭을 막되 세로 스크롤·확대와 키보드 사용을 보존한다. 이미지 모서리·캐릭터 장식·방향 전환 효과·모바일 배경 처리를 제공하며 동작 줄이기 설정을 따른다.
- `/series/[seriesId]`는 목록으로 돌아가기, 제목·소개·대표 이미지·총 편수, 첫 글부터 읽기와 전체 챕터 목록을 초기 HTML로 제공한다. 각 챕터는 연속 번호·제목·요약·최초 발행 날짜와 기존 글 주소를 제공한다.
- 포스트 상세는 시리즈 이름·소개·상세 링크, 접이식 전체 챕터, 현재 글, 현재 위치/편수·진행 막대와 이전·다음 글을 제공한다. 막대는 현재 글의 위치이며 실제 열람·완료 기록이 아니다. 없는 방향과 시리즈가 없는 글의 탐색 영역은 숨긴다. 공통 메뉴는 시리즈 진입과 현재 경로 표시를 제공한다.
- 비활성 슬라이드는 접근성 트리·포커스에서 제외하고 전환 결과를 알린다. JavaScript가 없어도 전체 시리즈 목록과 글 링크를 읽을 수 있다. Figma 등록 토큰·Light/Dark·1200px 반응형 경계를 유지한다.
- canonical은 `https://jengyoung.co.kr/series` 또는 `/series/{seriesId}`의 절대 주소로 만들고 보기 쿼리·해시는 제외한다. 제목·설명·공유 메타데이터를 제공하며 공개 시리즈만 사이트맵에 추가한다.

## 5. 검증

- Vitest로 새 항목·빈 필드·JSON 오류·작성 값 보존·반복 생성·최신 공개 집계·중복 정렬값·날짜 정렬·이미지 경계·초안 격리를 검사한다.
- Playwright E2E는 실제 원고로 목록·캐러셀·상세·챕터 이동·직접 접속·URL 상태·키보드·모바일 스와이프·JavaScript 없는 읽기를 검사한다. 테스트 목적으로 실제 원고를 수정하거나 공개하지 않는다.
- Light/Dark·mobile/desktop과 빈 상태·단일 항목·대표 이미지 유무·긴 내용·없는 ID를 확인하고, 실제 확인한 항목과 미검증 항목을 구분한다.

개발자가 수집·화면 구현을 검증할 때는 저장소 루트에서 다음 명령을 사용한다.

```sh
pnpm --filter web test --project=node
pnpm --filter web test:e2e:preview app/series/page.preview.e2e.spec.ts
```

수집 테스트는 임시 폴더를 정리하며 실제 원고를 변경하지 않는다. 앱 E2E는 실제 초안을 읽는다. 공개 빌드 E2E 전에 시리즈 제목·소개와 이미지 참조를 완성해야 하며, 공개 본문·과거 버전 전환의 검증에는 실제 공개 원고가 필요하다.

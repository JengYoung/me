# 포스트·일기 목록 정렬 계약

`/posts`와 `/diary`에서 독자가 선택하는 정렬 옵션과 URL 동작을 정의한다. 콘텐츠의 공개 판정·버전·날짜 의미는 [저장 계약](storage.md)을 따른다. [시리즈 계약](series.md)의 `order`와 챕터 순서는 이 정렬의 대상이 아니다.

## 1. 정렬 옵션과 기본값

| 페이지 | 표시 이름 | `sort` 값 | 기준 |
| --- | --- | --- | --- |
| `/posts` | 최신순 | `newest` | 최초 발행일 `createdAt` 내림차순. 기본값이다. |
| `/posts` | 오래된순 | `oldest` | 최초 발행일 `createdAt` 오름차순. |
| `/posts` | 최근 수정순 | `updated` | 최신 공개 버전의 `publishedAt` 내림차순. |
| `/diary` | 최신순 | `newest` | 기록 날짜 `entryDate` 내림차순. 기본값이다. |
| `/diary` | 오래된순 | `oldest` | 기록 날짜 `entryDate` 오름차순. |

- 포스트의 `createdAt`은 최초 공개 버전 `1.0.0`의 `publishedAt`에서 계산한다. 수정본을 발행해도 최초 발행일과 기본 정렬 순서는 바뀌지 않는다.
- 최근 수정순은 버전 번호로 선택한 최신 공개 발행본의 `publishedAt`을 비교한다. `X`, `Y`, `Z` 변경을 모두 포함하므로 오탈자 수정본도 정렬에 반영한다. 수정본이 없는 글은 최초 발행일을 사용한다.
- 정렬을 위해 작성자가 입력할 `createdAt`·`updatedAt` 등 새 메타데이터를 추가하지 않는다. 정렬 옵션은 글의 기본 버전 선택 기준이나 발행 여부를 바꾸지 않는다.
- 일기는 발행 시각이 아닌 기록 날짜를 비교한다. 최근 수정순이나 수정 이력 메타데이터를 일기에 추가하지 않는다.
- 어떤 옵션에서도 같은 날짜·시각이면 ID 오름차순으로 정렬한다. 오래된순에서도 동률의 ID 순서를 뒤집지 않는다.
- 포스트 시각은 시간대를 포함한 원본 값의 실제 시점으로 비교한다. 일기는 검증된 `YYYY-MM-DD`인 `entryDate`를 사용한다. 화면에 표시한 날짜 문자열·파일 수정 시각·수집 순서로 대체하지 않는다.

## 2. URL·탐색·canonical

- 정렬 선택의 URL 값은 `?sort=newest`, `?sort=oldest`, 포스트 전용 `?sort=updated`다. 기본값을 선택하면 `sort`를 생략한 `/posts`, `/diary`를 사용하며, 명시적인 `sort=newest`도 같은 기본값으로 읽는다.
- `sort`가 없거나 빈 값·알 수 없는 값이면 해당 페이지의 기본값으로 표시한다. `/diary?sort=updated`처럼 그 페이지에서 지원하지 않는 값도 기본값으로 처리한다.
- 화면의 선택 표시와 목록 순서는 같은 URL 상태를 사용한다. 직접 접속·새로고침·주소 공유·브라우저 뒤로가기와 앞으로가기에서 선택한 정렬을 복원한다.
- 정렬을 바꾸어도 목록의 글 수와 공개 대상은 그대로 유지한다. 여러 발행본을 별개 글로 나열하지 않는다.
- canonical은 정렬 쿼리·해시를 제외한 `https://jengyoung.co.kr/posts`, `https://jengyoung.co.kr/diary`다.

## 3. 이어서 결정할 사항

아래 항목은 미확정이다. 기존 화면이나 구현 편의에 따라 임의로 확정하지 않는다.

- 로컬 미리보기에서 최초 발행일이 없는 포스트 초안의 배치와 초안끼리의 순서.
- 정렬 선택 UI의 형태와 배치, 모바일에서의 표시 방식.

공개 목록의 초안 제외는 그대로 유지한다. 로컬 정렬을 위해 날짜를 임의로 만들거나 초안을 공개 발행본으로 바꾸지 않는다.

## 4. 구현 시 검증할 동작

- 포스트의 세 옵션과 일기의 두 옵션에서 선택한 날짜 기준과 ID 동률 처리가 일치한다.
- 포스트에 새 수정본을 추가해도 기본 정렬은 유지되고 최근 수정순에는 새 발행 시각이 반영된다. 첫 발행본만 있는 글도 최근 수정순에 포함된다.
- 시간대 표기가 달라도 같은 실제 시점이면 ID 기준을 적용한다. 일기의 순서는 `publishedAt`이나 파일 수정 시각의 영향을 받지 않는다.
- 직접 접속·선택 변경·새로고침·뒤로가기·앞으로가기에서 URL, 선택 표시, 목록 순서가 일치한다. 잘못된 값과 일기의 미지원 값은 기본값으로 복구된다.
- 정렬별 글 수·공개 대상·canonical이 유지된다. 로컬 미리보기 검증을 위해 실제 원고의 날짜·공개 상태를 수정하지 않는다.

정렬 함수·옵션 처리의 단위 검증은 Vitest, 실제 페이지의 URL·화면 연결은 Playwright E2E로 확인한다. 계약 문서 작성은 제품 동작 검증을 대신하지 않는다.

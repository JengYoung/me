# 로컬 콘텐츠 발행 절차 계약

이 문서는 로컬 명령으로 새 공개 발행본을 준비하는 절차와 자동화 범위를 정의한다. 저장 경로·공개 여부·버전 분류·자산 보존은 [콘텐츠 저장·발행·수정 이력 계약](storage.md), 아티클 작성과 컴포넌트 사용은 [아티클 Markdown·MDX 계약](mdx.md)을 함께 따른다.

로컬 명령은 공개 파일 준비와 계약 검증까지 담당한다. 작성자는 결과를 확인해 Git에 반영하고 별도 배포 절차로 공개한다. 작성 명령은 `apps/web/docs/posts`와 `apps/web/docs/diary`를 지원한다. 포스트는 버전별 발행, 일기는 단일 원고 직접 수정을 사용한다. 시리즈는 [시리즈 계약](series.md)에 따라 자동 수집한 JSON의 제목·소개·대표 이미지 참조를 작성한다.

초안 미리보기는 일반 개발 명령 `pnpm --filter web dev`에 포함되어 있다. 실제 `apps/web/docs/posts`의 `0.x.x` 원고는 `http://localhost:3000/posts`, `docs/diary`의 연도별 원고는 `http://localhost:3000/diary`, 시리즈는 `http://localhost:3000/series`에서 확인한다. 포스트의 기존 `.local.md`와 일기의 `{entryId}.local.mdx`도 읽는다. `content:preview`도 같은 `dev`를 실행하므로 개발 화면과 미리보기를 별도 서버로 구분하지 않는다. 원고를 복사·이동·공개 버전으로 승격하지 않는다. 빈 날짜·기존 시리즈 정렬값을 그대로 두고, 본문과 JSON·이미지 변경을 감지해 갱신한다. 개발용 생성물과 빌드를 공개 빌드에서 분리하고, 초안은 검색·사이트맵에서 제외한다. 이 명령은 아래 발행 명령과 별개다.

## 일기 작성 명령

| 명령                                     | 동작                                                                                                                                 |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `pnpm diary:new [entryId]`               | ID·제목·기록 날짜·요약·태그를 입력해 `diary/{year}/{entryId}.mdx` 하나를 만든다. `--local`은 대신 `{entryId}.local.mdx`를 만든다.    |
| `pnpm diary:edit [entryId]`              | 현재 원고 경로를 보여준다. 같은 파일을 직접 수정하며 사본이나 버전 파일을 만들지 않는다.                                             |
| `pnpm diary:publish [entryId]`           | 필수 메타데이터·MDX·이미지를 검증하고 단일 원고에 최초 `publishedAt`을 설정한다. 로컬 초안은 같은 연도의 `{entryId}.mdx`로 전환한다. |
| `pnpm diary:publish [entryId] --dry-run` | 같은 발행 계획을 검증하되 원고를 변경하지 않는다.                                                                                    |

- 새 일기는 `--title "제목" --entry-date YYYY-MM-DD`, 최초 발행은 `--published-at "2026-10-22T15:00:00+09:00"`으로 비대화형 실행할 수 있다. 누락된 필수 입력은 대화형으로 받으며 기록 날짜로 발행 시각을 추정하지 않는다.
- 새 원고의 연도 폴더는 `--entry-date`에서 정한다. 한 연도에 여러 원고를 만들 수 있으며 모든 연도에서 중복 ID를 거부한다. 수정·발행 명령은 ID로 원고를 찾고 `/diary/{entryId}` 주소를 유지한다.
- 일기의 `--series`, `--order`, `--bump`, `--reason`, `--from` 옵션과 시리즈·수정 이력 메타데이터를 지원하지 않는다. `{entryId}.mdx` 하나를 직접 수정하고 이미 발행한 원고의 최초 발행 시각을 유지한다. 공개 원고를 수정하면 다음 빌드·배포에 현재 내용이 반영되며 공개된 이전 본문을 별도로 보존하지 않는다.
- 일기 이미지는 같은 연도 폴더의 원래 파일을 참조한다. 발행 시 복사하거나 버전 접두어를 붙이지 않는다. 공개 원고가 `.local.` 자산이나 다른 폴더·누락된 이미지를 참조하면 거부한다.
- `content:validate`는 공개 포스트와 일기를 함께 검사한다. `--drafts`는 양쪽의 초안도 검사한다. Git HEAD 기준 공개 버전 보존 검사는 포스트에만 적용하며 일기 직접 수정을 막지 않는다.
- 일기 발행도 검증 후 파일을 교체하며 실패 시 임시 파일·잠금을 정리한다. 잠금·임시 파일은 ID별로 구분해 같은 연도의 다른 기록을 덮어쓰지 않는다. 자동 커밋·푸시·외부 배포는 실행하지 않는다. 기존 `.md` 일기는 이관·공개하지 않는다.

## 포스트 작성 명령

저장소 루트에서 바로 실행한다. 각 명령의 `--help`에서 비대화형 인자도 확인할 수 있다.

| 명령                                   | 동작                                                                                                                      |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `pnpm post:new [postId]`               | ID·제목·요약·태그·시리즈·정렬값을 터미널에서 입력하고 `0.0.0.mdx`를 만든다. `--local`은 `0.0.0.local.mdx`를 만든다.       |
| `pnpm post:edit [postId]`              | 기존 초안이 있으면 경로를 보여준다. 없으면 번호상 최신 공개 본문과 이미지 참조를 유지한 초안을 만든다.                    |
| `pnpm post:publish [postId]`           | 초안·변경 분류·발행 시각·선택적 이유로 새 공개 MDX와 필요한 이미지만 준비한다.                                            |
| `pnpm post:publish [postId] --dry-run` | 같은 발행 계획과 검증을 수행하고 공개 파일을 추가하지 않는다.                                                             |
| `pnpm content:validate`                | 공개 포스트·일기와 시리즈 JSON을 검증한다. 포스트는 버전·메타데이터·MDX·이미지와 Git HEAD 기준 공개 파일 보존도 검사한다. |
| `pnpm content:validate --drafts`       | 공개 검사와 함께 글마다 현재 미리보기 초안도 검사한다.                                                                    |

- 새 글의 ID는 소문자 영문·숫자·하이픈을 사용하고, 같은 ID와 새 글의 시리즈 정렬값 중복을 거부한다. 시리즈는 실제 원고의 `series.id`에서 선택하거나 새 ID를 입력한다. `order`는 간격을 허용하는 정렬값이고 화면의 N번째 글과 다르다. 기존 원고의 중복 정렬값을 자동 보정하지 않는다.
- 새 초안의 `publishedAt`은 비워 둔다. 수정 초안을 만들 때는 이전 발행 시각과 변경 이유를 비우되, 본문·제목·태그·시리즈·이미지 참조는 유지한다. 이미 작성 중인 초안은 덮어쓰지 않는다.
- 최초 공개 버전은 `1.0.0`이다. 수정 발행은 `--bump major|minor|patch` 또는 대화형 X/Y/Z 선택으로 번호상 최신 공개 버전에서 증가시킨다. 이전 X 계열에 별도 수정본을 추가하는 명령은 제공하지 않는다.
- 기본 발행 대상은 미리보기와 동일한 최신 초안이다. 다른 초안은 `--from 0.0.0.local.md`처럼 같은 글 폴더의 파일명으로 명시한다. 기존 `.md` 초안도 읽지만 결과 `.mdx`의 구문 검증을 통과해야 한다.
- 발행 시각은 대화형 입력에서 현재 시각을 제안하고 작성자가 확인한다. 비대화형은 `--published-at "2026-10-22T15:00:00+09:00"`처럼 시간대를 포함해 명시한다. 기존 원고의 날짜 의미를 추정해 이관하지 않는다. `--reason`은 선택 입력이며 초안에 작성된 이유도 보존한다.
- 초안과 초안 이미지는 발행 후에도 남긴다. 다음 발행 때 같은 초안 이미지를 참조하더라도 내용이 기존 공개 이미지와 같으면 해당 공개 파일을 재사용한다. 내용이 달라진 경우에만 새 버전 이미지와 참조를 준비한다.
- Markdown·JSX·정적 이미지 import를 구문 분석해 실제 이미지 참조만 변경한다. 코드 블록의 예제 경로나 일반 링크를 일괄 치환하지 않는다. 안전하게 특정할 수 없는 참조는 오류로 표시한다.
- 파일은 임시 경로에서 검증한 뒤 기존 파일을 덮어쓰지 않는 방식으로 기록한다. 실패하면 이번 실행이 만든 공개 파일만 정리한다. 글별 `.publish.lock`으로 동시 발행을 막고 종료 시 정리한다. 강제 종료로 잠금이 남았으면 실행 중인 발행이 없음을 확인한 뒤 해당 잠금을 제거하고 다시 실행한다.
- `content:validate`는 원고·이미지를 수정하지 않는다. 시리즈 JSON은 작성 필드를 보존하며 새 ID와 공개 집계를 갱신한다. Git HEAD에 있는 공개 포스트 파일·이미지의 변경과 삭제를 검출하며, 새 공개 여부를 결정하는 lock·등록 목록을 만들지 않는다. Git 이력이 없는 작업 공간은 HEAD 보존 검사 건수가 0이다. 모든 과거 커밋의 소급 변경이나 원격 배포 검증을 대신하지 않는다.
- `web build`는 공개 콘텐츠 검증과 목록 생성 후 Next.js 빌드를 수행한다. 발행 준비 명령 자체는 전체 앱 빌드·커밋·푸시·배포를 실행하지 않는다.

다음 1~3절의 버전·자산 사본 준비 절차는 포스트에 적용한다. 일기는 위의 단일 원고 절차를 따른다.

## 1. 작성부터 공개까지

| 순서                | 작성자와 도구의 역할                                                                                                                                                |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 초안 작성·미리보기  | 작성자는 `0.x.x.mdx`와 필요한 초안 자산을 준비하고 로컬에서 내용을 확인한다. 이미 공개된 이미지를 그대로 사용할 때는 그 파일을 참조한다.                            |
| 발행 대상 선택      | 로컬 명령에 카테고리·콘텐츠 ID·대상 초안을 지정한다. 최초 발행은 `1.0.0`, 수정 발행은 변경 성격에 맞는 `X/Y/Z` 분류를 준비한다. 변경 이유 `reason`은 선택 입력이다. |
| 공개 파일 준비      | 명령은 전체 본문·메타데이터를 담은 새 공개 MDX를 준비한다. 기존 이미지 참조를 유지하고, 실제로 추가·변경한 이미지에 필요한 공개 파일과 참조만 준비한다.             |
| 계약 검증·결과 확인 | 명령은 콘텐츠 계약을 검증하고 이전 버전·새 버전, 추가한 파일, 재사용한 이미지, 검증 결과를 표시한다. 작성자는 실제 변경 내용을 확인한다.                            |
| Git 반영·배포       | 작성자가 결과를 커밋·푸시하고 정해진 배포 절차를 진행한다. 배포가 성공해 사이트에 반영되어야 독자가 새 발행본을 읽을 수 있다.                                       |

- 변경 분류의 의미와 복합 변경의 우선순위는 기존 `X.Y.Z` 계약을 따른다. 글의 적용 환경·사실 오류·문장 수정 여부에 따라 작성자가 분류하며, 파일이 수정됐다는 이유만으로 특정 단계를 선택하지 않는다.
- 최초 발행에는 이전 공개 버전이 없다. 초안을 이전 공개 버전처럼 연결하지 않는다.
- 최신 공개 버전은 날짜가 아닌 `X.Y.Z`의 숫자 비교로 선택한다. 기존 frontmatter 구조를 유지하고, 작성자가 제공한 `reason`이 있으면 새 발행본에 보존한다. 이유 입력을 강제하거나 자동 생성하지 않는다.
- 발행 명령의 완료 범위는 공개 MDX·필요한 자산 준비, 계약 검증, 결과 표시다. 자동 커밋·푸시·외부 배포는 이 명령에 포함하지 않는다.
- 공개 파일을 준비한 시점과 사이트에 실제 반영된 시점을 구분한다. 로컬 명령의 성공을 배포 완료로 표시하지 않는다.
- 공개 대상으로 검증할 파일의 기준은 계속 버전 번호다. 준비·배포 단계를 구분하기 위해 별도의 `status`나 공개 목록을 추가하지 않는다.

## 2. 변경하지 않은 이미지는 복사하지 않는다

- 새 글 버전에서도 같은 이미지를 사용하면 기존 공개 파일을 그대로 참조한다. 글 버전과 이미지 파일명의 버전을 맞추기 위해 복사·이름 변경·참조 교체를 하지 않는다.
- 이미지 파일명의 버전은 그 이미지가 추가되거나 변경된 공개 버전이다. 사용하는 글의 버전과 같을 필요가 없다.
- 글의 제목·본문·메타데이터만 바뀌고 이미지가 그대로라면 새 이미지 파일을 추가하지 않는다.
- 이미지를 추가하거나 변경할 때는 작성자가 준비한 해당 파일만 새 공개 버전의 자산으로 처리한다. 초안 이미지 파일을 사용했다면 새 공개 버전 파일명으로 복사하고, 새 MDX의 해당 참조를 갱신한다. 이미지의 그림·내용을 자동 생성하는 기능은 이 발행 절차에 포함하지 않는다.
- 기존 공개 이미지의 내용과 과거 MDX의 참조는 보존한다. 새 발행본에서 사용하지 않는다는 이유로 이전 이미지를 삭제하지 않는다.
- 이미 공개 버전 이름으로 준비된 새 자산을 처리할 때도 불필요한 사본을 추가하지 않는다. 동일한 대상 경로의 파일을 다른 내용으로 덮어쓰지 않는다.
- Markdown 이미지 문법과 JSX 컴포넌트의 이미지 props에 같은 자산 규칙을 적용한다. 공개 MDX에 초안 이미지 참조가 남으면 검증 오류로 처리한다.

예를 들어 글이 세 번 발행되어도 이미지가 같다면 파일 하나를 계속 사용한다.

```text
1.0.0.mdx → ./1.0.0.이미지1.png
1.0.1.mdx → ./1.0.0.이미지1.png
1.1.0.mdx → ./1.0.0.이미지1.png
```

이후 `1.1.1.mdx`에서 이미지의 오탈자를 고친다면 작성자가 수정한 이미지에 대해서만 `1.1.1.이미지1.png`를 준비한다. 이전 세 발행본과 `1.0.0.이미지1.png`는 그대로 유지한다.

## 3. 검증과 결과 표시

- 기존 공개 버전과 대상 버전의 충돌, 기존 공개 파일의 변경, 필수 메타데이터 누락, 이미지 누락·초안 이미지 참조, 이전 공개 버전 연결을 검사한다. 메타데이터는 저장 계약의 기존 필드와 `reason?: string`을 따르며, 세부 버전 문법과 기존 필드의 필수·빈 값 검증은 구현 시 구체화한다. `reason` 생략은 검증 실패가 아니며, 제공된 값이 문자열이 아니면 오류로 처리한다.
- 검증 실패 시 성공으로 보고하지 않고, 문제가 있는 대상과 이유를 표시한다.
- 결과에는 카테고리·콘텐츠 ID·사용한 초안, 이전 공개 버전과 새 버전, 변경 분류, 작성된 `reason`, 추가한 MDX·자산과 재사용한 자산, 검증 결과를 포함한다. 최초 발행의 이전 버전은 없음을 표시하고, 작성되지 않은 `reason`은 생략한다.
- 공개 파일 준비 결과를 보고할 때 Git 반영과 실제 배포가 후속 단계임을 알린다. 발행 명령 실행만으로 사이트에 공개됐다고 안내하지 않는다.

## 4. 이어서 결정할 항목

| 항목                  | 결정할 내용                                                     |
| --------------------- | --------------------------------------------------------------- |
| 기존 원고 이관        | 원래 날짜의 의미, 최초 발행 시각의 해석과 실제 공개 대상        |
| 이전 버전 계열의 수정 | 최신 X 계열과 별도로 이전 X 계열에 수정본을 추가하는 정책       |
| 실제 배포             | 배포 대상·브랜치·트리거, 배포 실패·재시도와 운영 반영 확인 절차 |

## 5. 구현 시 검증할 계약

다음은 후속 구현의 완료 조건이며, 문서 작성만으로 통과한 것으로 보고하지 않는다.

- 최초 발행과 수정 발행에서 선택한 초안과 변경 분류에 맞는 공개 MDX가 준비된다.
- `reason`을 생략한 발행도 성공하며, 제공한 문자열은 그대로 보존한다. 문자열이 아닌 값은 오류로 표시한다.
- 본문만 수정한 발행에서는 새 이미지 파일이 생기지 않고, 기존 이미지 참조가 유지된다.
- 신규·변경 이미지가 있는 경우 그 자산만 새 공개 파일로 준비되며, 바뀌지 않은 이미지와 과거 발행본은 유지된다.
- Markdown과 JSX 이미지 참조 모두에 공개 여부·누락·보존 검증이 적용된다.
- 기존 공개 버전·자산을 덮어쓰지 않고, 검증 실패를 성공으로 표시하지 않는다.
- 실행 결과에서 새 파일·재사용 자산·검증 결과를 확인할 수 있고, 커밋·푸시·외부 배포가 자동 실행되지 않는다.
